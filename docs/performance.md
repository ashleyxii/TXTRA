## 2. 解決されたボトルネックと最適化手法 (Optimizations Implemented)

従来の $O(N^2)$ 級の走査コストとヒープ確保の多発を、以下のアーキテクチャ改良で解消しました。

```
[従来の推計比率]                                      [最適化後のアプローチ]
1位: maskEscapes / unmask (正規表現とMap生成) ── 55%  ==>  エスケープ記号なし行の完全バイパス (Fast Path)
2位: unmask 内の replaceAll ループ (O(K×N))   ── 25%  ==>  単一正規表現による O(N) 1パス一括置換
3位: 1行あたり 5〜6 回の連続 RegExp 呼び出し  ── 15%  ==>  文字コード・コロン位置走査による RegExp-free 化
4位: インデント計算の正規表現 & 文字列置換    ──  5%  ==>  文字走査によるゼロアロケーション (indent.js)
```

1. **一括 unmask の $O(N)$ 1パス化**:
   - `result.replace(/\x01(?:CODE|ESC)_\d+\x02/g, m => store.get(m))` により、エスケープが数千個あっても 1 回の文字列走査で復元。
2. **Fast Path によるエスケープ処理バイパス**:
   - 行内に `` ` `` も `\` も含まれない場合（通常行の 90% 以上）、`maskEscapes` の Map 生成および正規表現呼び出しを完全スキップ。
   - 仮想改行展開（`expandVirtualNewlines`）も、`.:` が含まれない場合は全文を即座にスルー。
3. **RegExp-free な行判定（文字コード・インデックス走査）**:
   - `colonIndex = masked.indexOf(':')` を起点とし、見出し（`:`）・ドット参照（`.`）・通常キーバリューを文字コード比較と `slice` だけで判定。
   - コロンを含まない通常テキスト行では、見出しやドット参照の正規表現エンジン呼び出しが一切発生しない。
4. **インデント計算のゼロアロケーション化 (`src/indent.js`)**:
   - 正規表現 `match` や `replace(/\t/g, ' ')` を廃止し、行頭の文字コード（32, 9）を走査してインデント深度と明示リスト記号（`- `, `* `）を算出。

## 3. Rust 化（`txtra-rs` / WASM / NAPI）における特性比較

Pure JS 版が「秒間 150 万行」に達した現在における、Rust 化の役割と位置づけ：

### ① 内部処理の劇的な進化（Rust の圧倒的優位点）
- **Zero-copy パース（`&str` スライス）**:
  - JS は行やトークンごとに新規文字列オブジェクトをヒープ確保しますが、Rust では入力テキストへのポインタと長さ（`&str`）だけで AST を構築できます。メモリ確保がほぼゼロになり、GC も存在しません。
- **SIMD による爆速探索 (`memchr`)**:
  - 改行文字やコロン、スペースの探索を AVX2 / NEON などの CPU ベクトル命令で並列処理（数 GB/s 走査）。
- **ステートマシン走査**:
  - `maskEscapes` のような退避処理自体が不要。Iterator で 1 文字ずつポインタを進めながら 1 パスで AST 化可能。

### ② 【要注意】JS から呼び出す際の「FFI 境界コスト」
Rust 化において最も重要なのは **「どこで呼ぶか」** です：

| 実行形態 | 速度特性 | 向き・不向き |
|---|---|---|
| **Rust ネイティブ CLI / サーバー** | **JS 比 30〜100倍 高速**<br>メモリ消費 1/10 | 大容量ログ処理、バックエンドHub、CLIに最適 |
| **Node.js (NAPI-RS)** | 大規模データ（1000行超）で **10〜30倍 高速**<br>小データ（数十行）では **Pure JS と同等または微遅** | C++バインディング同様、境界での文字列コピーが発生 |
| **Webブラウザ (WASM)** | 計算自体は爆速だが、JS ↔ WASM メモリ転送オーバーヘッドあり | ブラウザで数万行を扱うなら有利、日常行数なら Pure JS が圧勝 |

### 結論
- **日常的な用途（対話・チャット・通常ドキュメント・エディタ）**: 最適化された **Pure JS（ゼロ依存、秒間150万行）** が最も身軽で配布性・起動速度に優れ、すでに人間の知覚限界を遥かに超える速度に到達。
- **将来の超巨大データ集約**: 数十万〜数百万行のログやストリームを扱う CLI やバックエンド用に **Rust 版 (`txtra-rs`)** を提供するのが理想的なエコシステム展開となる。
